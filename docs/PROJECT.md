# PROJECT — dota-kill-clipper

Статус спеки: **черновик, НЕ утверждена** (ждём ответов на вопросы из `SCENARIOS.md`).

## 1. Цель
Во время обычной записи экрана в OBS автоматически сохранять короткие клипы с моими убийствами в Dota 2,
раскладывая их по папкам матчей с понятными именами. Никакого ручного монтажа.

## 3. Как определяем убийство
GSI-пакет содержит `player.kills`, `player.deaths`, `player.assists`, `player.kill_streak`,
`map.clock_time` (игровое время, с), `map.game_time`, `map.matchid`, `map.game_state`, `hero.name`.
Убийство = рост счётчика `player.kills` между пакетами (при `game_state` = `DOTA_GAMERULES_STATE_GAME_IN_PROGRESS` или `PRE_GAME`).
Дабл/трипл в одном пакете = рост на 2–3 → серия. Алгоритм уже проверен в `dota-helper-app/d2pt/events.py`.

## 4. «Команда запуска для логов каждой секунды» (напоминание)
Есть два разных источника, оба уже настроены на этой машине:

1. **GSI (Game State Integration)** — то, что нужно этому плагину. Это не параметр запуска, а cfg-файл
   `…\dota 2 beta\game\dota\cfg\gamestate_integration\gamestate_integration_<имя>.cfg`,
   Dota сама шлёт JSON по HTTP на указанный порт каждые `throttle` секунд (0.1–0.5 с). Плагин поднимет свой
   cfg на своём порту (например 3220), рядом с уже существующими `_helper.cfg` (3210) и `_d2pt.cfg` (53000).
2. **console.log** — параметры запуска Steam → Dota 2 → Properties → Launch Options:
   `-console -condebug -conclearlog` (уже стоят для dota-console helper). Даёт текстовый лог консоли, но
   убийства там ненадёжно; для плагина не нужен.

## 5. Архитектура — варианты

### Вариант A — Python-скрипт внутри OBS (Tools → Scripts) — рекомендуется, если решим вопрос с Python
- Интерфейс: нативная панель свойств скрипта в OBS (поле «Папка клипов» с диалогом выбора, длина буфера, порт GSI, включить/выключить).
- Внутри скрипта: поток с `http.server`, принимающий GSI; логика серий; вызов `obs_frontend_replay_buffer_save()`;
  по событию `OBS_FRONTEND_EVENT_REPLAY_BUFFER_SAVED` — `obs_frontend_get_last_replay()` → ffmpeg режет по границам → кладёт в папку матча.
- Плюсы: «настоящий плагин», один процесс, всё в OBS.
- Риск: OBS 32 собран под стабильный ABI `python3.dll`, документация заявляет Python 3.6–3.12; на машине только 3.14.
  Нужна отдельная установка Python 3.12 x64 (не конфликтует с 3.14) и указание пути в OBS → Scripts → Python Settings.

### Вариант B — внешняя программа + obs-websocket
- Отдельный процесс на Python 3.14 (как d2pt): GSI-приёмник + управление OBS через obs-websocket 5 (включить сервер в OBS, пароль).
- Интерфейс: маленькое окно (tkinter) или локальная веб-страница.
- Плюсы: не зависит от версии Python в OBS, легко тестировать, можно запускать автостартом.
- Минусы: два процесса, ручное включение websocket-сервера, это не «плагин OBS» в строгом смысле.

### Вариант C — нативный C++ плагин (libobs)
- Максимально «плагин», но сборка/CMake/Qt, недели работы. Не рекомендуется.

## 6. Как получаем видеофрагмент — варианты

### Вариант 1 — Replay buffer (рекомендуется)
- OBS держит последние N секунд в памяти (буфер повтора). Скрипт включает буфер при старте записи, при завершении серии
  вызывает сохранение, получает файл и ffmpeg-ом вырезает ровно `[first_kill − 10 с; last_kill + хвост]`.
- Требует: длина буфера ≥ (макс. длина боя + 20 с), например 90–120 с; лимит памяти буфера поднять с 512 МБ до ~1.5 ГБ
  (2560×1440 NVENC ≈ 25–50 Мбит/с → 120 с ≈ 400–750 МБ).
- Replay buffer в Advanced-режиме переиспользует кодировщик записи → нагрузки почти не добавляет.
- Клип появляется через ~10–15 с после последнего убийства.

### Вариант 2 — Пост-нарезка из файла записи
- Скрипт помечает времена убийств относительно старта записи и режет клипы, когда файл записи закрыт
  (у пользователя split каждые 15 мин → клипы появятся не позже чем через 15 мин; бой на границе split-файла = склейка двух файлов).
- Плюсы: никакого буфера в памяти, ничего в OBS не трогаем.
- Минусы: задержка, сложнее с границами файлов.

### Резка ffmpeg
- `-c copy` (без перекодирования): мгновенно, без потери качества, но границы привязаны к ключевым кадрам (±1–2 с при keyint 2 с).
- Перекодирование через NVENC: точные границы, несколько секунд GPU на клип.
- hybrid_mp4/mp4 от OBS ffmpeg открывает нормально.

## 7. Структура папок и имена (предложение)
```
<Корень клипов>\
  2026-09-09 21-35 pudge (match 8954164528)\
    [00.23.37-00.23.57] 1 kill (KDA 3-1-2).mp4
    [00.31.02-00.31.40] 3 kills (KDA 6-1-4).mp4
    match.json            # id матча, герой, список убийств, KDA, пути клипов
```
- Папка матча создаётся при первом убийстве (чтобы не плодить пустые папки за игры без убийств) — вопрос к пользователю.
- В имени клипа `:` недопустим в Windows, поэтому `00.23.37`.
- Время — `map.clock_time` (то, что на игровом таймере), отрицательное до рога показывается как `-00.00.45`.

## 8. Критерий готовности
- Тестовый матч (бот-игра или демо-режим с `matchid` = 0 тоже засчитываем): 1 одиночное убийство и одна серия из 2–3 →
  в папке матча ровно 2 клипа, длины ≥ 20 с, границы соответствуют убийствам, имена по схеме, `match.json` заполнен.
- Юнит-тесты: детектор серий (окна, дабл-килл в одном пакете, реконнект, пауза), вычисление границ клипа, именование.
- Ничего не сломано в текущей записи OBS (запись продолжает идти, split-файлы на месте).

## 9. Вне рамок (пока)
- Клипы смертей/ассистов, командные убийства, оверлеи/титры, загрузка куда-либо, поддержка Linux/macOS.
